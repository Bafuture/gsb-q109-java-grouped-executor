> 分支说明：`main` 为初始环境；`A`、`B` 为两次独立执行各自的工作分支，均从 `main` 的同一个提交拉出。

## 运行方式

```bash
./mvnw -q verify
```

## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们要处理一批消息，同一个业务 ID 的消息必须按顺序处理，不同业务 ID 之间可以并行，用来把吞吐提上去。请从零实现一个分组并发执行器。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 提交任务时指定分组键，同一个键的任务严格按提交顺序串行执行；2) 不同分组之间并行执行，全局并发度可配置，超过并发度的任务排队等待；3) 支持分组空闲回收：某分组一段时间没有新任务就释放执行资源，之后再来任务要能重新建立；4) 单个任务抛异常不得影响同组后续任务与其他分组，失败要记录并可通过回调感知；5) 支持优雅停止：停止接收新任务，等待队列中已有任务处理完（可配置超时）；6) 测试覆盖同组串行、跨组并行、并发度限制、空闲回收后重建、异常隔离与优雅停止；`mvn -q verify` 一条命令跑通。

## 提交要求

2. `./mvnw -q verify` 必须通过。
3. 完成后在所属分支（A 或 B）上提交，产物快照的父提交必须是初始环境快照。
